# backlog-kanban ロードマップ

## 進め方

- マイルストーンは develop から main へマージする単位にする。層ごと (パーサーだけ、画面だけなど) ではなく、薄くても端から端まで動かして確認できる単位で区切る
- 完了条件をすべて満たしたら、リリース前のコードレビューを経て main へマージする
- 完了条件の確認の手段は、CLAUDE.md の「動作確認」を参照する
- 順番と区切りは案。進めながら見直す

## M1: 開いているプロジェクトのバックログを表示する

WSL に接続したウィンドウで、開いているプロジェクトのバックログを3列のカンバンで見られ、.vsix でインストールして日常的に使い始められる状態にする。

着手前に、「完了」列の表示のしかた、優先度の区別の付け方、テストの構成を決める。

### 実施すること

- 拡張機能のひな形を作成し、CLAUDE.md の「ディレクトリ構成」「コマンド」を確定する
- バックログのパーサーと、そのフィクスチャを使った単体テスト
- ワークスペースのフォルダからのプロジェクト名の解決 (pj-status と同じ順)
- カンバンを開くコマンドと、VSCode のテーマに追従する3列の表示
- .vsix の作成とインストールの手順を README などに書く

### 完了条件

- [ ] 3つのセクション・優先度・詳細メモ (`>` 行) を含むバックログを、正しいステータス・優先度・メモに分けられることをテストで確かめている
- [ ] セクションが空のバックログ、タスクが0件のバックログを読んでも、エラーにならないことをテストで確かめている
- [ ] 書式に合わない行が「解釈できなかった行」として残ることをテストで確かめている
- [ ] プロジェクト名の候補が origin のリポジトリ名 → git のトップディレクトリ名 → ディレクトリ名の順に出ることをテストで確かめている
- [ ] 実機: WSL に接続したウィンドウでコマンドを実行すると、開いているプロジェクトのバックログが3列で表示され、各列の並びがファイルの順と一致する
- [ ] 実機: 進行中のタスクに詳細メモが表示される
- [ ] 実機: バックログのファイルがないプロジェクトで開くと、ファイルがないことが画面に出る
- [ ] 実機: VSCode のテーマをライトとダークで切り替えると、カンバンの色も追従する
- [ ] 実機: .vsix をインストールした VSCode で、上と同じ表示ができる

## M2: 自動更新と他のプロジェクトへの切り替え

カンバンを開いたままにしておけば常に最新の状態が見え、他のプロジェクトにも切り替えられる状態にする。

着手前に、カンバンを開く入口 (コマンドパレットだけか、ステータスバーにも置くか) を決める。

### 実施すること

- `backlog-data` のフォルダの監視と、表示中のプロジェクトのファイルが変わったときの描き直し
- `backlog-data` にあるプロジェクトの一覧と、表示の切り替え
- ワークスペースを開いていないときや、該当するファイルがないときに、一覧から選ぶ画面

### 完了条件

- [ ] `backlog-data` のフォルダからプロジェクトの一覧を作れることを、フィクスチャのフォルダでテストで確かめている
- [ ] 実機: カンバンを開いたまま backlog スキルでタスクのステータスを変えると、タブを開き直さずに表示が変わる
- [ ] 実機: 表示中ではない別のプロジェクトのバックログが変わっても、表示中のカンバンは変わらない
- [ ] 実機: 一覧から別のプロジェクトを選ぶと、そのプロジェクトのカンバンに切り替わる
- [ ] 実機: ワークスペースを開いていないウィンドウで開くと、プロジェクトの一覧から選ぶ画面が出る
- [ ] 実機: 表示中のプロジェクトのバックログのファイルを削除・移動すると、ファイルがないことが画面に出る

## M3: Windows ローカルのウィンドウへの対応

Windows ローカルのフォルダを開いたウィンドウでも、WSL 側のバックログを M1・M2 と同じように見られる状態にする。

着手前に、Windows ローカルのウィンドウでの自動更新の方式 (ファイル監視で足りるか、読み直しを併用するか) を決める。

### 実施すること

- `wsl.exe` と `wslpath -w` による `backlog-data` のパスの解決と、その結果をセッション中に覚えておく処理
- 設定でフォルダのパスを直接指定できるようにする
- 決めた方式での自動更新

### 完了条件

- [ ] 設定でパスを指定したときは、自動の解決より設定の値が使われることをテストで確かめている
- [ ] パスの解決に失敗したとき (`wsl.exe` がない、WSL が起動できないなど) に、解決の処理を表示のたびに繰り返さないことをテストで確かめている
- [ ] 実機: Windows ローカルのフォルダを開いたウィンドウで、そのプロジェクトのバックログが表示される
- [ ] 実機: Windows ローカルのウィンドウで、WSL 側から backlog スキルでタスクを更新すると、決めた方式のとおりに表示が更新される
- [ ] 実機: パスを解決できない状態 (設定に誤ったパスを入れるなど) で開くと、データの置き場所が見つからないことと、設定で指定できることが画面に出る
- [ ] 実機: WSL に接続したウィンドウでの表示が、M2 までと変わらない
