# backlog-kanban ロードマップ

## 進め方

- マイルストーンは develop から main へマージする単位にする。層ごと (パーサーだけ、画面だけなど) ではなく、薄くても端から端まで動かして確認できる単位で区切る
- 完了条件をすべて満たしたら、リリース前のコードレビューを経て main へマージする
- 完了条件の確認の手段は、CLAUDE.md の「動作確認」を参照する
- 順番と区切りは案。進めながら見直す

## M1: 開いているプロジェクトのバックログを表示する

WSL に接続したウィンドウで、開いているプロジェクトのバックログを3列のカンバンで見られ、.vsix でインストールして日常的に使い始められる状態にする。

### 実施すること

- 拡張機能のひな形を作成し、CLAUDE.md の「ディレクトリ構成」「コマンド」を確定する
- バックログのパーサーと、そのフィクスチャを使った単体テスト
- ワークスペースのフォルダからのプロジェクト名の解決 (pj-status と同じ順)
- カンバンを開くコマンドと、VSCode のテーマに追従する3列の表示
- .vsix の作成とインストールの手順を README などに書く

### 完了条件

- [x] 3つのセクション・優先度・詳細メモ (`>` 行) を含むバックログを、正しいステータス・優先度・メモに分けられることをテストで確かめている
- [x] セクションが空のバックログ、タスクが0件のバックログを読んでも、エラーにならないことをテストで確かめている
- [x] 書式に合わない行が「解釈できなかった行」として残ることをテストで確かめている
- [x] プロジェクト名の候補が origin のリポジトリ名 → git のトップディレクトリ名 → ディレクトリ名の順に出ることをテストで確かめている
- [x] 実機: WSL に接続したウィンドウでコマンドを実行すると、開いているプロジェクトのバックログが3列で表示され、各列の並びがファイルの順と一致する
- [x] 実機: 進行中のタスクに詳細メモが表示される
- [x] 実機: バックログのファイルがないプロジェクトで開くと、ファイルがないことが画面に出る
- [x] 実機: VSCode のテーマをライトとダークで切り替えると、カンバンの色も追従する
- [x] 実機: .vsix をインストールした VSCode で、上と同じ表示ができる

## M2: 自動更新と他のプロジェクトへの切り替え

カンバンを開いたままにしておけば常に最新の状態が見え、他のプロジェクトにも切り替えられる状態にする。

カンバンを開く入口は、コマンドパレットに加えてステータスバーにも置く (docs/plan.md の「カンバンを開く入口」を参照)。

### 実施すること

- ステータスバーの入口 (常に表示し、クリックでカンバンを開く)
- `backlog-data` のフォルダの監視と、表示中のプロジェクトのファイルが変わったときの描き直し
- `backlog-data` にあるプロジェクトの一覧と、表示の切り替え
- ワークスペースを開いていないときや、該当するファイルがないときに、一覧から選ぶ画面

### 完了条件

- [x] `backlog-data` のフォルダからプロジェクトの一覧を作れることを、フィクスチャのフォルダでテストで確かめている
- [x] 実機: ステータスバーの左側に入口が出ていて、クリックするとカンバンが開く。ワークスペースを開いていないウィンドウでも出ている
- [x] 実機: カンバンを開いたまま backlog スキルでタスクのステータスを変えると、タブを開き直さずに表示が変わる
- [x] 実機: 表示中ではない別のプロジェクトのバックログが変わっても、表示中のカンバンは変わらない
- [x] 実機: 一覧から別のプロジェクトを選ぶと、そのプロジェクトのカンバンに切り替わる
- [x] 実機: ワークスペースを開いていないウィンドウで開くと、プロジェクトの一覧から選ぶ画面が出る
- [x] 実機: 表示中のプロジェクトのバックログのファイルを削除・移動すると、ファイルがないことが画面に出る
- [x] 実機: origin のリポジトリ名とディレクトリ名が違うフォルダで、ディレクトリ名のバックログだけがあるときに開き、あとから origin のリポジトリ名のバックログを作ると、開き直さずに origin のリポジトリ名のカンバンに変わる
- [x] 実機: 上のフォルダで両方のバックログがあるときに origin のリポジトリ名のファイルを削除すると、ディレクトリ名のカンバンに変わり、作り直すと origin のリポジトリ名のカンバンに戻る
- [x] 実機: 表示中のファイルを削除して「見つからない」画面が出たとき、探したファイル名に開いているフォルダの候補が全て出ていて、どれかのファイルを作るとそのカンバンが出る
- [x] 実機: 一覧から選んだプロジェクトの表示中にそのファイルを削除すると、開いているフォルダのプロジェクトへ移らずに「見つからない」画面が出て、作り直すと元のカンバンに戻る
- [x] 実機: マルチルートのワークスペースで先頭のフォルダを入れ替えると、プロジェクトを選んでいなければ、新しい先頭のフォルダのプロジェクトのカンバンに変わる

## M3: Windows ローカルのウィンドウへの対応

Windows ローカルのフォルダを開いたウィンドウでも、WSL 側のバックログを M1・M2 と同じように見られる状態にする。

自動更新は、Windows 側のファイル監視が `\\wsl.localhost` の変更を受け取らないため、一定間隔で確かめて読み直す (docs/plan.md の「自動更新」を参照)。

### 実施すること

- `wsl.exe` と `wslpath -w` による `backlog-data` のパスの解決と、その結果をセッション中に覚えておく処理
- 設定でフォルダのパスを直接指定できるようにする
- `\\wsl.localhost` のパスを読むときの、一定間隔 (3秒) の確認による自動更新。タブが見えている間だけ確かめ、前に出たときにもすぐ確かめる

### 完了条件

- [ ] 設定でパスを指定したときは、自動の解決より設定の値が使われることをテストで確かめている
- [ ] パスの解決に失敗したとき (`wsl.exe` がない、WSL が起動できないなど) に、解決の処理を表示のたびに繰り返さないことをテストで確かめている
- [ ] 実機: Windows ローカルのフォルダを開いたウィンドウで、そのプロジェクトのバックログが表示される
- [ ] 一定間隔の確認で、前回と更新日時・サイズ・ファイルの一覧が変わったときだけ読み直すと判定することをテストで確かめている
- [ ] 実機: Windows ローカルのウィンドウで、WSL 側から backlog スキルでタスクを更新すると、開いたままのカンバンが数秒以内に変わる
- [ ] 実機: Windows ローカルのウィンドウで、カンバンのタブを裏に回している間に WSL 側で更新し、タブを前に出すとすぐに変わる
- [ ] 実機: Windows ローカルのウィンドウで、VSCode のファイル監視 (createFileSystemWatcher) でも `\\wsl.localhost` の変更が届かないことを確かめ、届くなら方式を見直す
- [ ] 実機: パスを解決できない状態 (設定に誤ったパスを入れるなど) で開くと、データの置き場所が見つからないことと、設定で指定できることが画面に出る
- [ ] 実機: WSL に接続したウィンドウでの表示が、M2 までと変わらない
